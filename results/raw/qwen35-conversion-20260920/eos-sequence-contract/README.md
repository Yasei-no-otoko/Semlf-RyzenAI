# CPU evidence: terminal EOS and returned sequences

Seven owned CPU toy cases, using AMD's installed OGA 0.14.0 environment, show that the configured terminal EOS ID is returned by `get_next_tokens()` but omitted from `get_sequence(0)`. The sequence is identical before and after `is_done()`. A non-EOS token reaching the configured maximum remains in the sequence. The scope is batch 1, greedy search, without beams.

All 54 saved sequence arrays are preserved byte for byte in `owned-fixtures-and-sequences.zip`, with their original relative names and SHA256. The archive also contains seven copies of the 388-byte owned `Add`/`OneHot` toy graph and seven tiny configurations. These contain only constants 1, 7 and [-10,10], not learned weights or any Qwen model data. No original model, AMD DLL, transaction archive, hardware snapshot, or public third-party source body is included.

`cpu-report.json` preserves all seven case rows and observed API values. `runtime-identity.json` preserves the recorded runtime binary hashes; the presence of a DLL in that inventory is not evidence that it executed. The report explicitly records device CPU, empty provider options, and zero NPU sessions. `source-diagnosis.json` gives official source URLs at the pinned revision with hashes and line references, but makes no claim that the installed binary is byte-equivalent to that source.

Run `python -B verify_cpu.py` with NumPy to verify all bundle hashes and independently compare the 54 saved arrays against the toy predictions. This verifier creates no runtime/model session. `recorded_cpu_probe.py` is the exact script that produced the observed CPU evidence, archived for provenance; its original local fixture/upstream-checkout dependencies are not bundled and it is not offered as a standalone runner. Its SHA is associated with every case in the original report.

The earlier failed NPU run did not save its fourth actual returned sequence or the following `is_done()` value. **These CPU toys do not reconstruct those missing NPU observations or turn that failed run into a success.** They disprove the unconditional test invariant that returned sequence must always include the final EOS, and motivate a fresh diagnostic with the actual values saved before assertion. The source diagnosis separately explains sampled-inclusive count, API-returned length, and processed/cache count.
